Terms used in every scene

Five facts the design keeps separate

The overall review question asks whether the scenes keep these apart. Scene 05 shows most of them side by side.

Worker completion
A worker reports that it has finished its part. That is not acceptance.
Evidence
Tests, logs, reviews and reports linked to the task and to a specific commit or artifact. Failed evidence stays visible.
Result submission
The executing hub submits a result. It references the delegation, the task version, the commit or artifact digest and the validation evidence.
Origin acceptance
The origin hub owns the task and makes the final acceptance decision. A transport acknowledgment or a worker completion never counts as acceptance.
Repository merge
A separate repository decision. Accepting a result does not merge its branch.

Planned, not built

How a request reaches the dashboard

  1. A developer asks for work or reviews a result in a supported AI client, such as Claude Code, Codex or Pi.
  2. The client integration calls Agentmux services. The services check access, own the work records and exchange commands and events through NATS. The planned shared persistence uses NATS JetStream behind those services.
  3. Authorized activity reaches the dashboard through the planned AG-UI integration and CopilotKit components. The dashboard shows the same task IDs, plan versions, evidence and acceptance state as the client.
  4. Review decisions return through an authorized service operation. Plan approval, task acceptance and repository merge remain separate decisions.

The terminal panels illustrate this interaction. They are not exact screenshots of a particular client or documentation of real commands. Available hooks, controls and conversation visibility depend on what each host supports.
