# Native macOS protected executable strategy

Status: research proposal for Codex review. No runtime, entry point, workflow, task or acceptance record was changed. No macOS execution is claimed. P02 still requires native macOS boot, shutdown and Compose evidence.

## Recommendation

Use a separately installed, root-owned, versioned protected release tree on native macOS. Verify its externally authorized assembly and the exact installed Mach-O bytes, then execute their fixed paths as the ordinary user. Keep the four existing protected roles as four independent processes with the same NATS account permissions, bounded supervision, EOF lifetime pipes and retained profile leases. Ordinary plugins and domain behavior remain outside this assembly. This is a proposed platform-specific execution backend, not a change to the language-neutral plugin ABI or a reason to add business behavior to the kernel.

This is a security inference from documented macOS permissions and normal path execution, not an already qualified implementation. Its guarantee is precise: an unprivileged runtime process cannot write, change permissions on, rename or replace the protected image or any controlling path component. Root and a deliberately authorized privileged updater remain trusted. It does not prevent a same-user debugger, process termination, stolen credentials or every form of runtime compromise.

Apple documents path-based execve. Go's Darwin child path calls execve with the executable path, arguments and explicit environment. Neither source establishes a portable sealed-file-descriptor equivalent to Linux memfd. [Apple execve](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/execve.2.html), [Go child execution](https://go.dev/src/syscall/exec_libc.go).

## Why a protected installation is necessary

A user-owned file made read-only is not sufficient: its owner can change its permissions. An executable can also be replaced through a writable ancestor directory. Apple's permissions documentation further states that ACLs affect access and that a volume with ownership checks disabled changes the access decision. Root ownership and mode bits therefore need verified ACL, ancestry and mount conditions. [Apple permissions](https://developer.apple.com/library/archive/documentation/Security/Conceptual/AuthenticationAndAuthorizationGuide/Permissions/Permissions.html).

Apple recommends opening without following symlinks, checking the opened object's type, ownership, permissions and links, and retaining descriptors. Its secure-file guidance also warns about remote mounts and unchecked writable locations. The installer and runtime should use descriptor-relative component traversal; checking a pathname and reopening it is insufficient by itself. [Apple secure file operations](https://developer.apple.com/library/archive/documentation/Security/Conceptual/SecureCodingGuide/Articles/RaceConditions.html).

Do not treat `/Applications`, a developer checkout, a user package manager or a user cache as inherently protected. Inspect actual metadata. A proposed fixed base is `/Library/Application Support/Agentmux/Protected/releases/<assembly-digest>/`; its location is a proposal, not proof that the actual host has safe ancestors. macOS filesystem indirection must be characterized on the native host, not rejected or approved solely from a string prefix.

## Proposed installation and admission rules

1. A bounded privileged install command or signed package enrolls a release into a fresh directory. It verifies the enrolled release authority and assembly compatibility, then each final binary digest. Do not run the launcher or kernel as root. Installation and an authorized update are distinct from ordinary terminal auto-launch; missing installation yields an actionable fail-closed prerequisite error.
2. Install manifests, public trust policy, executables and every controlling ancestor under root ownership. Use no group/other write bits, no setuid/setgid executable bits, regular executable files with one hard link, and no runtime-writable aliases. Reject symlinks within the release tree. Hold actual directory/file descriptors while validating each component.
3. Validate filesystem ACLs on those same descriptors, including ancestor deletion/child replacement rights. Prefer a conservative policy that rejects write-granting ACLs rather than attempting a broad principal/group resolver. Unknown ACL or mount status fails closed. Never infer safety from chmod alone or from a successful access() call made by a more privileged verifier.
4. Require a local approved filesystem with ownership enforcement enabled. Inspect the actual mount via fstatfs, its flags and device identity; do not accept remote, ownership-ignoring or user-mounted substitutes. Account explicitly for the host's APFS system/data layout. A filesystem name alone is not an authority claim. [Apple statfs](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/statfs.2.html).
5. A release directory is write-once for legitimate installers. Updates install a new digest directory and select a new version for future groups. Never alter, remove or reuse an active version's pathname. Coordinate installer cleanup with all users' live protected groups, not one local profile's advisory lock. Unauthorized root modification is outside the guarantee; accidental privileged update races must still be prevented by the updater contract.
6. Prepare verifies the external signed release policy and final installed bytes. Immediately before each spawn, revalidate the retained image/path identity and digest, plus protected ancestry. The command object contains only the fixed admitted path and explicit literal arguments. There is no fallback to a user-writable staging copy. An implementation may need the private executable interface to return a preparation/start validation error; do not hide validation failure in a fake command.
7. Preserve private per-user credentials, state and leases outside the root-owned executable tree. The ordinary user can launch already installed code automatically; installation or update must never be silently elevated by that launch.

Privilege elevation should be limited to the install operation. Apple's guide warns against running general applications with elevated privileges and describes separation of privileged and ordinary work. This proposal does not require a permanently running privileged service or setuid kernel. [Apple privilege separation](https://developer.apple.com/library/archive/documentation/Security/Conceptual/SecureCodingGuide/Articles/AccessControl.html).

## Signatures and executable dependencies

The enrolled Agentmux release authority, exact assembly digest, compatibility membership and exact final binary hashes remain the admission authority. Compute the shipped hashes after final code signing: signing can change Mach-O bytes. Apple's ordinary codesign verification validates signature consistency, but an explicit additional requirement is needed to restrict signer identity. A merely valid self-selected signature is not our release approval. [Apple code-signing checks](https://developer.apple.com/library/archive/documentation/Security/Conceptual/CodeSigningGuide/Procedures/Procedures.html).

For distributed builds, validate the expected code identity, apply the intended hardened-runtime policy, and use Apple's signed/notarized delivery path where required. Keep production Developer ID/notarization verification distinct from CI fixture signatures and ad-hoc test binaries. No Apple account or private signing key is needed to research ordinary-user pathname protection. Public distribution credentials must not be invented or copied into evidence. [Apple distribution signing](https://developer.apple.com/documentation/xcode/creating-distribution-signed-code-for-the-mac/).

Darwin is not static ELF. The inspected pinned Go 1.27.2 linker emits `/usr/lib/dyld`, references `/usr/lib/libSystem.B.dylib`, and can create an ad-hoc code signature. Therefore CGO_ENABLED=0 is not evidence of a Linux-equivalent no-loader Mach-O image. Inspect the actual native binary load commands and allow only the needed protected OS loader/libraries; reject user paths, relative libraries, unapproved @rpath/@loader_path dependencies and embedded arbitrary load paths. Retain the supervisor's explicit environment allowlist, with no inherited DYLD injection variables. [Go Mach-O linker](https://go.dev/src/cmd/link/internal/ld/macho.go).

Apple's dyld design also describes OS libraries served from a shared cache. Native admission must account for that approved OS loading mechanism; it must not require every named system dylib to exist as a separate regular file. Record the actual native Mach-O/cache behavior and platform trust assumptions. A load-command prefix alone does not establish that the bytes are OS-protected. [Apple dyld design](https://github.com/apple-oss-distributions/dyld/blob/main/doc/dyld4.md).

Filesystem ACL inspection has a concrete implementation cost. Apple provides acl_get_fd_np for descriptor ACL retrieval and acl_get_entry for entry traversal/freeing. The pinned x/sys package inspected here has fstatfs but no generated acl_get_fd_np or Getattrlist wrapper. The simplest auditable candidate is a very small Darwin-only native ACL adapter, with no new domain service. A CGO adapter changes native build qualification and must be explicitly approved; a CLI text parser or handwritten undocumented attribute layout is not automatically simpler or safer. Do not implement the backend without resolving this choice. [Apple descriptor ACL API](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_fd_np.3.html), [ACL entry API](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/acl_get_entry.3.html).

## Existing descriptor research stays separate

Current snapshot_unsupported.go refuses all non-Linux production preparation. snapshot_darwin_test.go stages the test Mach-O, unlinks it, checks a read-only write/reopened-writer attempt, and tries /dev/fd/3. It records sameUIDImmutabilityProven=false even on execution success. Preserve its actual native result and fail-closed control unchanged as history. A successful descriptor launch alone does not prove that the owner cannot change file flags/permissions, obtain another writer or replace the loaded dependencies.

The current platform-foundation workflow already has a separate macos-15 darwin-research job and always uploads failed research evidence. The normal native job qualifies only fail-closed refusal for Darwin runtime. Neither a cross-build, the unlinked probe nor mocked native CI validates a new protected-install backend.

## Required native qualification before enabling the backend

| Boundary | Required actual native test |
| --- | --- |
| Valid release | Privileged fixture install into a disposable protected base; ordinary-user Prepare/Start of all four signed-bound roles; real NATS readiness/late snapshots; exact source, install metadata, architecture and final image hashes. |
| Ordinary-user modification | Separate ordinary process tries byte overwrite, truncate, chmod, rename, unlink, replacement and new hard/symbolic links before/after Prepare and while Start is deliberately paused. Verify each denied operation and actual executed marker/digest; a copied writable tree must demonstrate that the mutation control really works. |
| Ancestry | Writable or wrong-owner parent; symlink component; changed final inode; unsafe hard link; ACL granting write/add-file/delete-child; unknown ACL; ownership-disabled/remote fixture or explicit unsupported diagnosis. Test real ACL operations on the native host. |
| Release authority | Wrong enrolled key, wrong assembly, altered final signed binary, different architecture, unsupported API, wrong role set, valid-but-unapproved signer. Never refresh a hash to make a changed image pass. |
| OS loader | Capture actual Mach-O commands and reject a real user-directory dylib fixture or injected DYLD environment. Verify the approved OS-library path without claiming arbitrary dependency immutability. |
| Recovery | Bounded start failure; exact owned Stop/StopRole and reap; killed launcher EOF cancellation and retained lease release using native process-exit observation, without adopting unrelated PIDs. Preserve an unrelated sentinel. |
| Update | Install version B without changing active A; keep A executing its exact approved bytes until owned shutdown; cleanup refuses active versions and never deletes user state/volumes. |
| Platform gate | Run native macOS Compose cold/warm/concurrent-owner/failure checks and the full remaining P02 criteria. This backend alone is not the phase gate. |

GitHub-hosted runners commonly offer elevated setup, but the test must record the actual executing UID/groups and attempted access results. Running the adversary as root would not test this boundary. A runner account with sudo capability proves only its non-elevated process behavior; it must not be labeled a non-admin-account qualification. If the requirement needs a genuinely non-admin account, provision a disposable account in a native fixture and use it for the kernel/adversary; retain only safe UID/group facts, not credentials.

## Decisions for Codex

Approve or reject (1) a root-owned protected-install backend as the Darwin counterpart to Linux sealing, (2) the fixed versioned base and active-version retention policy, (3) a small Darwin ACL adapter/native build dependency, and (4) fixture trust versus production Apple identity requirements. Record these as explicit additions to the platform admission and installer contract, preserving protected membership, NATS-only post-bootstrap communication and trusted plugins first. These are Codex architecture choices within the authorized task; no Ryan/Nick gate is requested. Until actual evidence passes, Darwin remains fail closed.

## Evidence and limits

Research performed on Windows/WSL on October 13, 2026, using official Apple and Go sources and the recorded repository inputs. No macOS host, installation, elevated operation, new process backend or mock qualification was run. Local source hashes and pinned Go/x/sys excerpts are in research.json. No credentials, keys, provider prompts, private user profiles or user data were read. Existing Linux evidence and all native-macOS requirements are preserved.
