# Protected process supervision

`Prepare(ctx, rawAssembly, packageDir, assembly.Trust, Limits)` verifies the fixed release, then independently checks the bytes staged for execution. Its result has private descriptors, not caller-selected executable paths. `Prepared.Start(ctx, [4]RoleOptions, Deadlines)` starts four direct child processes. Each role ID must appear exactly once. Arguments stay literal; no shell is involved. Environment values use a fixed key allowlist, and role/API identity is supplied internally. The child inherits no host environment and starts at `/`.

On Linux and WSL, staging uses executable `memfd` files with write, growth, shrink, seal and executable-mode seals. It seals first, then re-reads and hashes the actual immutable descriptor against the trusted digest. It checks ELF type and host architecture from those immutable bytes and rejects `PT_INTERP` and `DT_NEEDED` dependencies. The initial protected Go foundation must be static; ordinary language-neutral plugin execution remains separate P03 work. It then passes a read-only descriptor as child fd 3 and executes `/proc/self/fd/3`. Original package changes after preparation cannot replace the sealed image. Missing executable-memfd support or denied seals fail closed; there is no path-based fallback. This requires the tested modern Linux kernel APIs, not merely successful cross-compilation. The mechanism follows [Linux memfd documentation](https://www.man7.org/linux/man-pages/man2/memfd_create.2.html) and [file seals](https://www.man7.org/linux/man-pages/man2/F_GET_SEALS.2const.html).

`Group` keeps only the `os.Process` objects returned by its own starts. One goroutine waits for each child. Stop sends TERM, then KILL after the grace period, and waits within the reap deadline. It never discovers or adopts a PID, signals a process group, or kills an unrelated process. Failed or canceled startup cleans up the already started children. Parent cancellation also stops this initial supervised lifecycle. Detaching a healthy runtime requires later explicit lifecycle ownership. Protected roles must not daemonize or create unmanaged descendants; this API stops direct children and does not pretend that an unknown descendant is owned. Output is capped at 32 KiB per role and marked truncated.

The size limits and context checks bound preparation work on local regular files. They do not promise that a blocked filesystem syscall can always be interrupted at an exact wall-clock deadline. Start deadlines cover the sequence of descriptor-based starts and cleanup; application readiness remains a separate NATS observation. A process being started is not a healthy kernel or application.

macOS remains an incomplete mandatory platform slice. Product preparation returns `ErrPlatformUnqualified`, without an insecure fallback. Apple documents path-based [execve](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/execve.2.html) and [posix_spawn](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/posix_spawn.2.html); these documents do not prove a Linux-equivalent seal. `snapshot_darwin_test.go` is a disposable native research probe for an unlinked staged Mach-O file inherited through read-only fd 3. It records actual descriptor execution or failure. Even successful execution would not prove same-UID immutability or qualify a production backend. An actual native macOS run, reviewed immutability strategy and candidate implementation are still required. Cross-builds cannot supply that evidence or narrow P02's native macOS boot and Compose requirements.

This is not a sandbox for trusted same-UID plugins, a release-authority enrollment mechanism, protection from a privileged debugger, or a guarantee about shared libraries. It launches no models/providers and owns no business state, broker credentials or Compose resources. The caller supplies an externally authenticated release and separate per-role configuration. Later integration must prove kernel accounts, protected-role readiness, healthy detachment and the remaining phase criteria.

Run the Linux real-subprocess fixtures with `go test ./runtime` in an isolated native source copy using the prepared Go 1.27.2 toolchain. The fixture builds a static Go child with CGO disabled and a separate CGO dynamic binary used only for admission denial; the latter needs the prepared native C compiler and is never executed. The tests execute only the static fixture, inspect its actual PID/output/exit state, test literal environment handling, replace source files after sealing, alter a real memfd before sealing, attempt writes to sealed descriptors, and verify an unrelated sentinel survives owned shutdown. The Darwin research test must run on an actual native host and retains its failure as evidence rather than silently skipping it.
