# Protected assembly verification

`Verify(raw, packageDir, trust)` checks the P01 `protected-assembly` contract before a later supervisor launches any member. It requires the four distinct roles, v1 schema/API, exact expected release version and authority reference, and verified binary bytes. It returns all four members in fixed order or no result. It starts no process and contacts no broker.

The host must obtain `Trust` from authenticated release policy outside the supplied assembly. `AssemblyDigest` covers the exact JSON bytes. `ReleaseManifestDigest` is the separate parent release reference already defined by P01; it cannot authenticate member declarations by itself. Comparing only that self-reported field would permit changed binaries and member digests to keep the old release reference. This package does not enroll authorities, verify a release signature, choose trusted keys or permit kernel replacement.

The JSON decoder rejects missing/unknown fields, duplicate keys, invalid Unicode and trailing data. Authority identifiers/revisions and digest/version forms match P01 common definitions. Member IDs must be distinct even when their other fields differ. Entry points use portable relative slash paths; absolute paths, traversal, backslashes, drive syntax and symlinks within the package are refused. The host-selected package root is canonicalized, then an `os.Root` handle confines file reads. Files must be regular and their SHA256 must match. All files used by tests are disposable synthetic files.

The returned paths are observations, not execution handles. Verification closes its file descriptors. Files or directory entries can change afterward, and a rename can make a returned path refer to another object. An in-place writer can also change a file during hashing. The supervisor must prevent writes for the verified release and bind actual execution to the checked objects, or use an equivalent reviewed mechanism that closes these races. Calling `Verify` immediately before path-based execution alone does not solve them. Executable format, mode and interpreter policy also belong to that supervisor. No race-free execution claim is made here.

The initial module preserves the accepted Go 1.27.2 and nats.go 1.54.0 spike pins. This package itself uses only the standard library. Run `go test ./kernel/assembly` in the `platform` module using the prepared toolchain and an isolated native filesystem source copy/cache. These checks qualify this verification slice; they do not complete P02-T02, boot, runtime permissions, Compose or supported-host acceptance.
