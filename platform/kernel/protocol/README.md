# Protected kernel protocol

This package supplies stateless parsing and local transport helpers for the four fixed protected roles. It is not an ordinary plugin ABI or an application authorization service. Each role runs its own process and broker connection. Local evaluation callbacks belong only to that process; peer traffic always uses NATS. Shared logger and clock interfaces are local context-owned references. No root broker client or broad host environment is inherited.

`LoadEnvironment` reads the exact supervisor-owned role, API major, instance/profile IDs, endpoint and private credential reference. The private JSON has `schemaVersion`, `role`, `username`, `password`, `natsUrl` and `scope`. Scope contains `hubId`, `instanceId`, `profileId`, `assemblyDigest`, `releaseManifestDigest` and `releaseVersion`. The file must be canonical, regular, private, owned by the current OS user and have one link. Its immediate parent must be private and owned. Only a role's own username/secret is supplied. Endpoint, role, API and instance/profile must match the supervisor environment. The launcher remains responsible for validating the externally trusted release and enrolled profile before writing these private files. No secret belongs in arguments, logs or exported observations.

`Open` takes a copied fixed subject set produced by `communication.Subjects`. It validates those names against the hub scope. Every event uses its role's exact event subject. Broker permissions bind that subject to its credential; a payload cannot claim another role. Command subjects identify the destination, not the sending identity. Only the safe `announce` action is implemented, with a bounded publication interval. No payload grants sender authority, starts/stops a process or changes the protected assembly. Actual bounded protected process controls and supervisor recovery remain integration work.

Events and commands use closed version `1.0.0` objects, capped at 8 KiB, with duplicate keys, malformed JSON, unknown fields and context/release/role mismatches rejected. Events carry incarnation, monotonic safe-integer revision, timestamp, state and fixed error codes. The lifecycle role adds four peer observations. Default heartbeat is one second; default staleness is three seconds. Only explicit local test settings may use smaller declared timings. Up to two seconds of timestamp skew are tolerated; receipt age is still bounded independently. Old revisions and retired incarnations cannot replace current observations. Peer restart history is capped at 32 retired incarnations per role and then fails closed.

Async NATS subscriptions and the actor input channel have explicit queue bounds. Oversized frames are discarded before entering the actor queue. Slow-consumer or permission faults terminate this scoped actor rather than silently claiming healthy delivery. Connection attempts and reconnects are bounded; disconnected peers become stale, and no buffered readiness messages are replayed as current. The enclosing supervisor still owns recovery. Closing a role publishes a bounded best-effort stopping observation, then closes its own connection. A missing stopping message is detected through freshness, not invented as a successful shutdown.

Exported `kernel-info` snapshots and updates are full observation frames, not L04 responses. They include a source incarnation/revision, observation/expiry times, release/context and four member observations. Snapshot publication repeats, so late subscribers receive the next full frame. `SnapshotCursor` rejects replay/retired sources and reports revision gaps or source changes explicitly. A full frame gives a consistent local view of collected observations; it does not claim a broker transaction across four role events or replay a durable event history. The status producer never includes invented work counts or connected hubs. Caller-scoped L04 services, signatures where required, persistence readiness, domain work and federation remain separate requirements.

The initial tests use private disposable brokers with static per-role credentials. These tests verify real NATS traffic and actor loops, but goroutine fixtures do not prove four independent supervised PIDs. Actual sealed-process integration, crash/restart and native host qualification remain required. Ordinary PluginContext/OperationContext construction and language-neutral package lifecycle remain P03 work.
